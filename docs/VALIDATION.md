# BatteryHelper 本机验证记录

验证日期：2026-10-09。设备：HONOR XWC-P，Core Ultra X7 358H / Intel Arc B390，Windows 11 25H2（26200.9550），主屏 3072×1920、200% 缩放。

## 已验证的数据

| 项目 | 结果与范围 |
|---|---|
| 电池 | Windows BatteryReport 可读取真实充电、放电功率和容量。本轮持续记录包含 549 个充电样本、1003 个放电样本。 |
| CPU | 使用已包含 Panther Lake 识别的固定 LibreHardwareMonitor 源码；安装 PawnIO 后，由 LocalSystem 服务读到 CPU Package 功率，普通权限界面可读取。 |
| GPU | 服务读到 Arc B390 的 GPU Power；普通权限直接探测时也验证了 Intel IGCL 能量差回退路径。 |
| 整机输入 | 本机未找到明确覆盖整机的输入传感器。充电时展示电池充电功率，并标为“充电”。 |
| 测量口径 | CPU 封装可能包含核显；CPU/GPU 独立展示，没有相加作为整机输入，也没有使用充电器额定功率。 |

示例真实样本：嵌入运行时显示“放电 24.7 W”，CPU 11.9 W，GPU 0.5 W。另一次充电样本为电池 60.5 W、CPU 17.6 W、GPU 0.5 W。这些是不同负载下的瞬时值，不代表固定功耗。

上游版本锁定 `76150732c2df9241415eec216001bec4557c9033`。补丁修正了驱动不可用时把未完成的 MSR 读取当作零值的问题，并在后续读取失败、长间隔或计数器重置时清空值、重新建立能量基线。

## 持续采集

`artifacts/validation/soak/summary.json` 记录 1801.1 秒测试，退出码 0，共 1554 个快照。其中 1552 个快照电池、CPU、GPU 均可用；另两个分别是连接初始化与供电切换后的恢复提示，按设计清空旧状态读数。

采样间隔平均 1.160 秒、最大 1.907 秒，没有超过 5 秒的间隔。该持续测试验证采集服务；任务栏嵌入界面是在测试后段切换的新实现，不能据此宣称嵌入界面已单独完成 30 分钟测试。

测试期间仍进行编译和界面预览，资源占用不属于空闲基准。采集服务工作集约 33–175 MiB。普通权限进程接口不能可靠读取 LocalSystem 服务累计 CPU 时间，因此 `resources.csv` 中服务 CPU 的零值不作为测量结果。界面栏包含预览进程及启动阶段，不能作为单一常驻进程的稳定内存值。

本机只有已验证的 Intel 核显，未完成独显休眠与持续唤醒检查。

## 任务栏嵌入验证

1.0.0 的父窗口、样式及点击命中检查曾通过，但用户截图和后续屏幕像素检查证明任务栏区域仍为空白。这些窗口状态不等于实际显示成功，先前仅凭窗口状态判断可见的结论已纠正。

1.0.1 将显示区域改为原生 GDI 子窗口，并启用 `WS_EX_LAYERED` 与完全不透明的分层窗口属性，使任务栏合成器真正显示文字。未创建桌面悬浮窗口。修复已通过实际任务栏区域截图确认；示例为“放电 15.7 W / CPU 9.0 W · GPU 0.0 W”，具体值随采样变化。

1.0.1 覆盖更新退出码 0，正式安装目录的界面以普通权限运行，采集服务为 Running，自启动指向 `C:\Program Files\BatteryHelper\BatteryHelper.exe --background`。正式版本实际画面见 `artifacts/validation/installed-visible-1.0.1.png`；销毁并重建显示子窗口后再次截图确认文字仍显示，见 `recreated-visible-1.0.1.png`，对应诊断记录中的挂载代数为 2。本轮未重启用户的 Explorer。

- 普通权限（`Administrator=false`）运行。
- 实际父窗口为 `Shell_TrayWnd`，`WS_CHILD` 样式生效；功率窗口位于任务栏内，中心点击命中本应用 HWND。
- 本机左侧位置为物理坐标 `(16,1828)–(512,1916)`，尺寸 496×88，对应 248×44 DIP。
- 左右切换立即保存；本机右侧无足够空位时隐藏显示并保留托盘，切回左侧恢复。没有桌面悬浮回退。
- 销毁并重建本应用的显示 HWND 后，挂载代数由 1 增至 2，后台读数继续更新。
- 已加入 `TaskbarCreated`、无效父窗口检查及托盘恢复处理；未主动重启用户的 Explorer 来进行真实重启验收。
- 任务栏 UI Automation 查询在后台线程进行；过期或无法确认的边界不会用于摆放显示。
- 100% / 150% / 200% 的布局算法检查通过，深浅色预览均已生成。实际系统缩放本轮只验证了 200%。

Win32 子窗口由任务栏承载，但 Windows 11 没有保证其内部窗口结构对第三方兼容。系统更新后可能需要适配；挂载失败仍保留托盘详情。

## 自动检查

31 项测试通过，覆盖 mW 转 W、方向、接电仍放电、输入优先与充电回退、无电池保留 CPU/GPU、查询未知、零值、缺失与过期、能量计数器重置/回绕、默认左侧及各缩放下的任务栏空位和拥挤情况。

服务和界面构建通过。界面不要求管理员权限，硬件采集由安装时配置的服务负责。命名管道只允许配置的本地用户、管理员和 LocalSystem，拒绝网络身份；服务没有客户端时关闭硬件采集。

## 验收边界

已记录真实充电和放电状态。接电未充电、接电仍放电、无电池及电池查询失败的显示规则通过自动检查；这些场景没有逐一在本机制造。

外接屏插拔、实际 100%/150% 系统缩放、任务栏自动隐藏、全屏游戏/视频、真实 Explorer 重启及休眠恢复仍需人工验收。同口径第三方监测工具对照未完成。

## 安装及恢复

最终安装包已通过安装与覆盖更新，安装进程退出码 0，服务为 Running。实际路径 `C:\Program Files\BatteryHelper`；服务账户为 LocalSystem，授权桌面用户匹配，界面普通权限读取命名管道。

自启动登记为正式安装目录的 `BatteryHelper.exe --background`。已修正带空格路径的服务更新参数以及安装子进程的 32/64 位注册表视图差异；在 32 位配置子进程中也验证成功。服务配置失败时，安装器返回退出码 10，跳过启动步骤并记录错误。

实际结束本应用采集服务进程后，Windows 服务恢复机制自动启动新实例。界面约 5.1 秒显示 CPU/GPU 为“— W”，随后自动重新连接并恢复真实功率，电池仍可通过本地接口读取。证据见 `artifacts/validation/service-recovery.jsonl`。

安装包包含运行时；不需要用户另行安装 .NET。当前应用安装包未进行代码签名，捆绑的 PawnIO 安装程序已验证有效签名。

1.0.0 正式安装版本曾进行约一分钟资源抽样，共每个进程 18 次记录（含启动阶段）：界面 CPU 平均 0.359%、峰值 0.835%，服务平均 0.087%、峰值 0.204%，均按全机逻辑处理器归一化。界面工作集 143–178 MiB，服务 154–159 MiB；工作集包括共享映射页面，不等同于任务管理器的专用内存列。此次使用系统性能计数器，避免把无法读取的服务累计 CPU 时间误判为零。证据见 `artifacts/validation/installed-resources-final.csv`。此次 1.0.1 显示修复未重新进行完整资源基准或 30 分钟界面测试。

左右位置切换及进程重启记忆已通过实机验证；最终恢复左侧。无客户端后连接采集服务，初始快照明确显示“采集已暂停”，随后恢复真实采样。

卸载进程退出码 0，确认应用文件、采集服务、自启动项和服务配置均不存在，PawnIO 共用驱动保留。随后重新安装恢复使用。登录自启动的登记路径已核对，本轮没有注销 Windows 来验证实际登录启动。
